# Функциональный аудит Wave — 25 октября 2026

Исходное состояние: `5a1976d`, ветка `fix/local-work-architecture`, Wave 0.6.0.
Проверка охватывает карту функций приложения, автоматические проверки,
разбор интеграций и доступные сценарии нативного Linux-приложения.
Это не сертификация всех платформ и внешних сервисов.

## Что исправлено

| Область | Ошибка и изменение | Подтверждение |
|---|---|---|
| Локальное аудио Linux | WebKit отклонял `asset:` как источник медиа. При конкретной ошибке поддерживается чтение в ограниченный по памяти blob; граф звука сохраняется. | Реальные WAV/MP3 и WebAudioAdapter tests |
| Полнота аудиофайла | Tauri отдаёт `Range` частями: первое чтение обрезало 90-секундный WAV до ~64 секунд. Теперь проверяются Content-Range и длина, читаются остальные части. Прокси раскрывает заголовки диапазона для WebView. | Нативный WAV восстановлен до 90 секунд; тесты диапазонов, лимитов и ошибок |

| Офлайн | Локальный файл без записи в каталоге загрузок ошибочно блокировался офлайн-режимом. Локальные URI проверяются до запрета сетевых источников. | streamResolver tests, включая похожий удалённый hostname |

Добавлено разрешение закрытия окон для уже существующих команд главного окна. | Сборка и clippy; запуск нового окна в GUI пока не подтверждён |

Нативные проверки выполнялись с временным профилем `/tmp/wave-functional-audit`,
без изменения пользовательской библиотеки. Аудио — синтетический тихий WAV 90 с
и его MP3-версия. Автоматизация обращалась к настоящему приложению через временно
подключённый сценарий и HTTP API; это не проверка всех действий мышью.
Сценарий удалён из HTML и репозитория, в production-сборку не входит.
[Результаты последнего завершённого нативного прогона](2026-10-25-native.json)
сохранены с исходным неуспешным результатом снятия блокировки; после этого
исправление проверено отдельным регрессионным тестом.

Повторный запуск после нативных изменений оказался заблокирован графической
сессией: GDB показал ожидание в GTK `wl_display_roundtrip_queue`, а при X11 —
в `xcb_connect_to_display_with_auth_info`, до запуска логики Wave. Поэтому новые
команды бэкапа/мини-плеера нельзя считать проверенными через интерфейс.
Пользовательская графическая сессия не перезапускалась.

## Оставшиеся проблемы и приоритеты

Эти пункты не исправлены данным набором изменений.

1. **P1 — Spotify: разрыв авторизации на нативном транспорте.**
   `SpotifyProvider` передаёт Basic/Bearer в `Authorization`, а
   `http_fetch_json` отбрасывает этот заголовок. Это подтверждено чтением обеих
   сторон контракта; реальный аккаунт не использовался. Нужен отдельный
   разрешённый транспорт Spotify с защитой токена и проверкой перенаправлений,
   затем проверка входа и поиска. Просто разрешать секретные заголовки для
   любых адресов не следует.
2. **P1 — незаметное временное хранилище при сбое SQLite.**
   `pickStorage` переходит на MemoryStorage, а `composeServices` не сообщает
   выбранный backend интерфейсу. Новые изменения могут исчезнуть после
   закрытия приложения. Нужен явный режим восстановления/индикатор хранения
   и защита от ложного впечатления, что данные сохранены на диск.
3. **P2 — большие локальные файлы на WebKit.**
   Восстановление через blob ограничено 32 МиБ и 8 секундами. Это намеренная
   защита памяти слабых устройств, но не решение для больших FLAC/длинных
   записей при отказе файлового протокола. Нужен потоковый локальный транспорт
   с авторизацией, Range и тестами больших файлов.
4. **P2 — повторное включение провайдера через HTTP API.**
   `ApiBridge.sourcesSet` фильтрует текущий массив провайдеров, из которого
   уже удалён заблокированный источник. Одного снятия блокировки недостаточно
   для восстановления экземпляра; нужна общая переконфигурация сервисов.
   Это результат чтения кода, не выполненный нативный сетевой сценарий.
5. **P2 — точность Wrapped.**
   `computeWrapped` складывает полные длительности начатых треков.
   Исправление дубликатов истории устраняет завышение от паузы, но не
   превращает эту оценку в фактические минуты прослушивания. Нужен учёт
   реально проигранного времени с паузами, перемоткой и пропусками.
6. **Готовность агента.** Чат и инструменты есть, законченной проверенной
   модели и встроенной установки/обновления runtime нет. Двухшаговый LoRA
   пилот подтверждает работу тренера, а не качество помощника.
7. **Приёмка устройств и сервисов.** Обязательны повторный GUI-прогон
   бэкапа/мини-плеера, Windows/macOS/Android, Cast, авторизация/синхронизация,
   реальные загрузки, обновление и длительное воспроизведение.

Плеер стал устойчивее, но перечисленные открытые пункты не позволяют объявить
весь продукт полностью проверенным и готовым к выпуску.
