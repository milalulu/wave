# Агент Wave: подключение, диалог и инструменты

Статус: работают контракт v1 и исполнитель всех 24 инструментов, подключённый к
сервисам Wave. Есть автономный стенд из 60 заданий для сравнения решений моделей.
Добавлены настольный чат, подключение к серверу локальной модели и отдельно
включаемое облако. Модель ещё не выбрана, не поставляется с приложением и не
дообучена. На Windows/macOS/Linux агент загружается по запросу после проверки
нативной возможности. Android и браузерная сборка исключают чат, адаптер и исполнитель.

## Как подключить

После сборки и перезапуска настольного приложения откройте «Агент» в боковом меню
или «Настройки → Агент Wave» (в том числе в узком окне).

1. Для локальной модели запустите совместимый сервер самостоятельно. Например,
   для Ollama базовый адрес — `http://127.0.0.1:11434/v1`. Укажите точное имя уже
   установленной локальной модели. Wave не устанавливает сервер и не скачивает веса.
   Принимаются только HTTP и loopback-литералы `127.0.0.1` / `[::1]`.
2. Для облака выберите режим «Облако», введите базовый HTTPS-адрес API, имя модели
   и сохраните ключ. Отдельно разрешите отправку сообщений и результатов команд
   этому серверу. При изменении адреса разрешение в форме снимается.
3. «Проверить подключение» отправляет только синтетическую фразу и проверяет
   формат ответа. Библиотека и история диалога в этой проверке не используются.
4. Примените настройки. Это завершает прежний диалог; его история не переносится
   между подключениями. После этого отправьте запрос, например «Что сейчас играет?».

Протокол — `POST <baseUrl>/chat/completions`, текстовые `messages`, `stream: false`.
В `content` ожидается JSON-решение Wave, а не нативный `tool_calls`.
Совместимость сверена с [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
и [Ollama](https://docs.ollama.com/api/openai-compatibility).
По умолчанию включён `response_format: {type:"json_object"}`; его можно отключить
для сервера без JSON mode, но валидация решения остаётся обязательной.
Экспериментальный пункт «Строгая схема» включает `response_format: json_schema`
с `strict: true` и короткое описание инструментов. Он выключен по умолчанию;
старые настройки сохраняют прежний режим. При неподдерживаемой схеме запрос
завершается ошибкой, автоматического перехода в JSON mode/облако нет.

В этом режиме ответ сервера имеет вид `{"decision": <решение Wave>}`. Объект
верхнего уровня и вложенный `anyOf` соответствуют ограничениям
[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs);
локальная проверка схемы использует [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs).
Адаптер проверяет и разворачивает только точную одноуровневую оболочку; история
ответов модели оборачивается обратно перед следующей отправкой. Пользовательские
сообщения и результаты инструментов не переписываются. Исполнитель сохраняет
контракт v1. Схема создаётся из каталога, в режиме просмотра в ней нет изменяющих
инструментов; запрет изменений дополнительно проверяет исполнитель.

Ограничения длины строк остаются в валидаторе Wave: некоторые runtime не принимают
их в грамматике. Поддержка остальных ограничений также зависит от сервера.
Формально допустимая команда может не соответствовать намерению пользователя;
строгая схема не делает непроверенную модель пригодной к управлению.
Проверка подключения использует только текстовые решения, без каталога инструментов.

Лимит генерации — 1024 токена; для локального сервера используется `max_tokens`,
для облака — `max_completion_tokens`. Параметр можно сменить в настройках.
Поддержка этих полей зависит от модели; автоматических повторов с другими полями нет.
Модели с большими обязательными затратами токенов на reasoning могут не уложиться в лимит.

Локальное подключение не переключается в облако при отказе. HTTP-клиент не использует
системный proxy и не следует редиректам. Сам локальный сервер может быть настроен
на облачную модель: Wave не может проверить место вычисления за его API. Для работы
на ПК без отправки в облако нужно выбрать локальные веса и соответствующий режим сервера.

Ключ хранится через [keyring 3.6.3](https://docs.rs/keyring/3.6.3/keyring/): Secret
Service в Linux, Credential Store в Windows, Keychain в macOS. Он привязан к полному
нормализованному адресу API, включая путь и порт, читается только нативным транспортом
и не возвращается в JS. При недоступном хранилище выдаётся ошибка; сохранения в
обычный конфиг или localStorage нет. В JS ключ присутствует лишь при вводе/отправке
в системное хранилище, после успешного сохранения поле очищается. Удаление ключа
выполняется для адреса, показанного в форме.

## Границы компонентов

```text
AgentView → AgentConversation → DesktopAgentModel → Tauri agent_model → сервер модели
                  ↑                                ↓ JSON в content
                  └──────── AgentDecision ──────────┘
AgentExecutor → WaveAgentTools: валидация → проверка контекста → вызов сервиса
          ↓ ToolResult
существующие PlayerEngine / контроллеры приложения / Storage
```

- [contract.ts](../../src/core/agent/contract.ts): типы аргументов, решений, публичных результатов и ошибок.
- [catalog.ts](../../src/core/agent/catalog.ts): 24 инструмента, JSON Schema аргументов и строгая проверка без приведения типов.
- [prompt.ts](../../src/core/agent/prompt.ts): общие правила для локальной и облачной модели.
- [protocol.ts](../../src/core/agent/protocol.ts): компактное описание, схема, преобразование истории и строгая проверка оболочки.
- [AgentConversation.ts](../../src/core/agent/AgentConversation.ts): цикл решений, история, отмена, лимиты и результаты команд.
- [agentModel.ts](../../src/app/agentModel.ts): настройки и модельный адаптер; ключей в интерфейсе модели нет.
- [agent_model.rs](../../src-tauri/src/agent_model.rs): настольный HTTP-транспорт, системное хранилище ключей и отмена запросов.
- [agentChat.ts](../../src/app/agentChat.ts): жизненный цикл чата независимо от выбранного экрана.
- [evaluation.ts](../../src/core/agent/evaluation.ts): оценка следующего решения без вызова сервисов Wave.
- [AgentExecutor.ts](../../src/core/agent/AgentExecutor.ts): очередь запросов, отмена, дедупликация и таймауты.
- [WaveAgentTools.ts](../../src/core/agent/WaveAgentTools.ts): исполнение команд и ограниченный реестр ссылок.
- [agentDesktop.ts](../../src/app/agentDesktop.ts): соединение с существующими сервисами и UI-контроллерами.
- [Проверочные задания и запуск](../../evals/wave-agent/README.md).

HTTP API и Lua сохраняют свои контракты. Модель не вызывает `ApiBridge.dispatch`
и не передаёт произвольный `Track`: текущий API допускает полные объекты и свободное
приведение аргументов. Агент работает через отдельные строго проверенные команды.

## Инструменты и привязка к существующему приложению

Все поля аргументов обязательны. Пустые аргументы передаются как `{}`. Неизвестные
поля, строковые числа, NaN, бесконечность и значения за пределами диапазона
отклоняются; приложение не подменяет запрос округлением или ограничением значения.
Список и численные ограничения в `catalog.ts` — источник истины.

| Инструмент | Смысл и точка исполнения |
| --- | --- |
| `wave_status` | Публичная проекция `engine.snapshot`; не отдавать полную очередь и внутренние Track. |
| `wave_search` | `searchAll`, фильтры активных источников и блокировок; максимум 20 результатов. Поиск не запускает музыку. |
| `wave_play` | `useApp.play([track])`, чтобы сохранить выбор источника и отмену прежнего запроса; заменяет очередь. |
| `wave_pause`, `wave_resume` | `engine.pause()` / `engine.play()`, без нового поиска. |
| `wave_next`, `wave_previous` | Существующие методы перехода PlayerEngine. |
| `wave_seek` | Абсолютные секунды; дополнительно проверять длительность текущего трека, затем `engine.seek()`. |
| `wave_volume` | Абсолютные проценты 0–100 через `useApp.setVolume`; 0 выключает звук. |
| `wave_queue` | Страница очереди, offset с нуля, limit 1–50; `currentIndex` относится ко всей очереди. |
| `wave_queue_add` | `engine.playNext()` либо `engine.addToQueue()`; текущий трек не прерывается. |
| `wave_queue_clear` | `engine.clearQueue()`, остановка и пустая очередь; не удаляет сохранённую библиотеку. |
| `wave_playlists`, `wave_playlist_get` | Чтение Storage, публичная проекция и постраничный результат. |
| `wave_playlist_create` | Общий контроллер создания плейлиста возвращает созданную запись; модель получает временный ID. |
| `wave_playlist_add` | Контроллер добавления с обновлением интерфейса и защитой от дублей. |
| `wave_playlist_play` | Получить полный плейлист из Storage, затем общий контроллер воспроизведения. Пустой плейлист — ошибка. |
| `wave_liked` | Постраничная публичная проекция `library.getLikedTracks()`. |
| `wave_like` | Общий `setLiked` явно устанавливает состояние и обновляет UI; повторный вызов не снимает лайк. |
| `wave_radio` | `useApp.startArtistRadio(artist)`; это радио по исполнителю, не отдельный генератор рекомендаций. |
| `wave_shuffle`, `wave_repeat` | `engine.setShuffle()` / `engine.setRepeat()`, явное состояние. |
| `wave_speed` | `useApp.setSpeed()`, 0.5–2 включительно, с существующим сохранением настройки. |
| `wave_equalizer` | `useApp.setEqualizer()`, десять полос в установленном порядке, −12…+12 dB. |

Позиции страниц и ID не взаимозаменяемы. `wave_play` принимает ID конкретной записи,
а не номер результата. При совпадающих названиях нужен уточняющий вопрос.
Добавление в плейлист допускает известную каталожную запись; воспроизведение и
добавление в очередь требуют `playable: true`.

В v1 нет удаления плейлистов и файлов, shell, произвольного HTTP, экспорта
библиотеки, доступа к ключам, смены облачного режима, управления источниками и
загрузки весов. Такие запросы получают `unsupported`, а не похожую команду.

## Контекст и результаты

`AgentTrack` содержит ID, название, исполнителя, длительность и доступность
воспроизведения. Он не содержит stream URL, пути файлов, токены или полный `meta`.
Исполнитель хранит соответствие выданных ID реальным сущностям в рамках сессии,
проверяет его при каждом вызове и заново проверяет существование сущности.
Нельзя использовать ID, который модель придумала или получила из текста названия.
Смена источника использует существующий RecordingCatalog, сохраняя библиотечный ID.

Названия, описания и прочие данные источников не являются инструкциями. Они не
могут расширять список инструментов или разрешать действия от имени пользователя.
В модель передаётся только необходимая страница данных. Облачный режим требует
выбранной пользователем настройки; исполнитель не подключает модели и не отправляет им запросы. Поиск музыки использует существующих провайдеров Wave.

Успешный результат имеет вид `{ok:true,data:...}`; ошибка —
`{ok:false,error:{code,message,retryable}}`. Типы результатов заданы по инструментам
в `ToolResults`; сообщения ошибок должны быть безопасными для передачи модели.
`loading` не означает, что звук уже играет. Пустой поиск не равен отказу источника.
`incomplete: true` сообщает о частичных результатах поиска.

Решение модели — только предложение следующего шага. `answer` и `clarify` не
исполняют команды. Сообщение об успехе допустимо только после фактического результата.
Изменение нескольких настроек — последовательность вызовов с проверкой каждого
результата, а не пакет параллельных изменений.

## Использование исполнителя

В нативном настольном приложении:

```ts
const session = await useApp.getState().openAgentSession();
const controller = new AbortController();
const result = await session.execute("turn-1:status", {
  type: "tool", name: "wave_status", args: {},
}, {
  allowedTools: ["wave_status"],
  signal: controller.signal,
});
// controller.abort() или session.cancel("turn-1:status") отменяет ожидание.
// useApp.getState().closeAgentSession() завершает всю сессию.
```

`allowedTools` задаёт доверенный вызывающий код для текущего запроса пользователя,
а не модель. Исполнитель проверяет этот список, схему, известность ссылок и состояние
плеера; он сам не понимает естественный язык и не определяет намерение пользователя.
Контроллер диалога выбирает фиксированный список из настроек: все 24 команды или
только команды чтения. Модель не может изменить режим. Соответствие действия
естественному запросу пока определяется моделью и инструкцией; это не отдельный
доказанный классификатор намерений. Качество и устойчивость конкретной модели нужно
проверять до повседневного использования.

Все команды одной сессии выполняются последовательно. Перед постановкой в очередь
аргументы копируются; внешняя мутация объекта не меняет ожидающее действие.
По умолчанию сессия принимает до 128 уникальных запросов (максимум 256), таймаут
запроса — 15 секунд, включая ожидание в очереди (настраиваемый максимум 60 секунд).
Повтор того же request ID возвращает сохранённый результат; другие аргументы с тем
же ID дают `request_conflict`. Записи не вытесняются, чтобы не повторить изменение.
При лимите нужна новая сессия; дедупликация не переносится между сессиями и перезапусками.

Публичные ID случайны и действуют только в своей сессии. Хранится не более 256 ссылок
на треки и 256 на плейлисты; старые ссылки вытесняются и требуют повторного чтения.
Даже локальный ID с путём к файлу не отдаётся модели. Результат страницы ограничен
50 записями, поиска — 20, текстовые поля сокращаются до 300 символов. Реестр берёт
сущности только из результатов сервисов, не из переданных моделью объектов Track.

Отмена до изменения запрещает его запуск. Отмена поиска не запускает найденные
треки; отмена подготовки радио не заменяет текущую очередь. Уже начатое агентом
воспроизведение останавливается при отмене, если пользователь не переключился на
другой запрос плеера. Позднее автопродолжение проверяет поколение воспроизведения.

Запись в SQLite нельзя считать отменённой только потому, что истёк таймаут.
В таком случае ошибка содержит `effect: "unknown"`; последующие команды ждут
реального завершения записи. `session.result(requestId)` возвращает окончательный
результат после завершения (до этого `null`). Повторная доставка того же ID не
повторяет запись. `effect: "not_started"` означает, что изменение не было начато.
Автоматических повторов нет. Успех после завершившейся записи не обещает откат.

`openAgentSession()` проверяет `desktop_agent_available` через Tauri; подмена
user-agent не включает агента. Параметр сборки `TAURI_ENV_PLATFORM` разрешает
ленивый модуль только для linux/windows/darwin/macos. Android, androideabi и сборка
без нативной платформы его исключают. При перенастройке сервисов сессия закрывается.

## Цикл диалога и пределы

Одновременно выполняется один запрос пользователя. Контроллер ждёт фактический
результат каждого инструмента, добавляет его в контекст и только затем обращается
к модели снова. Ответы модели и результаты Wave показаны раздельно; текст модели
не является доказательством исполнения. После ошибки инструмента ход заканчивается.
Модель не получает скрытые внутренние Track, URL аудиопотоков или ключи.

- Не более восьми инструментов и девяти обращений к модели на ход.
- Ход ограничен 180 секундами, нативный запрос — 65 секундами с учётом получения
  ключа (HTTP — 60 секунд, подключение — 5 секунд).
- Сообщение пользователя — до 2000 символов; модельный контекст — до 80 сообщений
  и 96 000 UTF-8 байт сериализованного массива. История не обрезается молча;
  при переполнении нужен новый диалог. Запрос на нативной стороне ограничен 100 000 байт.
  В режиме схемы эти пределы включают преобразованную историю и схему; сама
  схема ограничена 32 000 байт. Сокращается исходная инструкция, история молча
  не обрезается. Параметры окна/потоков/режима thinking задаются сервером;
  контролируемый профиль измерителя не переносится автоматически в подключение UI.
- HTTP-ответ — до 65 536 байт, `content` — до 16 000 байт. Отказ, обрезанная генерация,
  неизвестные поля решения или неверные аргументы не исполняются.
- Повтор одинакового изменяющего действия в одном ходе останавливается.
  Диалог не хранится на диске и не попадает в синхронизацию аккаунта.

«Остановить» отменяет запрос модели и дальнейшие шаги; поздний ответ не исполняется.
Закрытие HTTP-соединения не гарантирует остановку вычисления на стороне сервера.
Выполненные изменения не откатываются. При `effect: unknown` новый ход блокируется,
а «Проверить исход команды» читает окончательный результат без повтора записи.
Если исход остался неизвестным, нужно проверить Wave перед ручным новым диалогом.
Закрытие и открытие сессии ждёт завершения прежних записей; это действует и при
перенастройке сервисов. Запуск радио агентом сохраняет экран чата и кнопку остановки.

## Проверки и следующий этап

Интеграционные тесты используют настоящий PlayerEngine, MemoryStorage, контроллеры
Zustand и тестовый аудиовыход. Проверяются последствия команд, UI-состояние библиотеки,
выбранный источник, отмена, ошибочное аудио, дедупликация и неизвестный исход записи.
Это не ручная проверка слышимого звука на всех трёх настольных ОС.

`pnpm agent:check-bundles` строит настольный, Android, Android armv7 и браузерный
frontend во временных каталогах и проверяет исключение инструментов, транспорта,
чата и его стилей. Проверка добавлена в CI. Нативный модуль и зависимости keyring
ограничены cfg Windows/macOS/Linux; Android не регистрирует модельные команды.
Набор заданий и эталонные ответы не включаются ни в одну сборку приложения.

Проверены сценарии с тестовой моделью через настоящие PlayerEngine и MemoryStorage,
UI чата, HTTP с локальным тестовым сервером, ошибки, редиректы и лимиты ответа.
Это не измерение качества нейросети. Дополнительно выполнена
[одна синтетическая проба](../../evals/wave-agent/smoke/2026-10-24-local.json)
уже установленной `entity12208/editorai:v2` (1.5B, Q4_K_M) через локальный Ollama:
HTTP 200, но решение не прошло схему; никаких команд плеера не выполнялось.
48,6 секунды включали холодную загрузку при параллельной сборке и не являются
замером производительности. После пробы модель выгружена.

Затем добавлен отдельный [стенд реальных моделей](../../evals/wave-agent/README.md)
с сырыми ответами, фиксацией параметров/весов, CPU/RAM-метриками, повторами после
выгрузки и изолированными цепочками через ядро. В [первичном сравнении](../../evals/wave-agent/runs/2026-10-24/README.md)
Qwen2.5:1.5b дала 29/60 правильных решений и 4/20 критических. Qwen3:1.7b дала
9 правильных из 30 полученных ответов, затем превысила 180-секундный диагностический
лимит; оставшиеся 29 заданий не запускались. Полного результата Qwen3 нет.
Ни одна модель не допущена к повседневному управлению; Qwen2.5 — только кандидат
для следующего эксперимента. Это результаты фиксированного CPU-профиля Ollama,
а не подтверждение качества всех режимов этих моделей или текущего UI-транспорта.

В [повторном сравнении со схемой и короткой инструкцией](../../evals/wave-agent/runs/2026-10-24-structured/README.md)
оба кандидата завершили 60 заданий: Qwen2.5 — 28 автоматических совпадений,
Qwen3 — 30. Корректность формата выросла, но модели продолжают ошибаться в выборе
действий и сообщать об успехе при состоянии loading. Новый режим экспериментальный
и выключен по умолчанию. Подготовлен [исходный корпус seed-v1](../../training/wave-agent/README.md):
28 обучающих и 6 dev-диалогов, плюс 8 отложенных диалогов вне Git. Сценарии
проверяются исполнением через ядро; в обучающий экспорт идут только train/dev.
Это ещё не дообученная модель: следующий шаг — разбор и расширение данных,
проверка токенизации/маски и пробный запуск обучения.
Измерение слышимого звука под нагрузкой, полный RSS,
минимальное целевое оборудование, облачные запросы и системные хранилища на трёх
ОС ещё требуют проверки. Встроенный inference runtime и загрузчик моделей
на этом этапе не добавлены; веса не устанавливаются вместе с Wave.
