# Данные для дообучения агента Wave

`seed-v1` — небольшой исходный корпус и воспроизводимый конвейер его проверки.
Диалоги составлены Codex для этого репозитория на синтетических треках. Пользовательская
библиотека, история приложения, внешняя модель-учитель и облачные API не использовались.
Исходники данных распространяются с лицензией репозитория; веса моделей сюда не входят.
Обучение весов на этом этапе **не выполнялось**.

| Часть | Диалоги | Семейства | Целевые решения |
| --- | ---: | ---: | ---: |
| Train | 28 | 14 | 128 |
| Dev | 6 | 3 | 26 |
| Отложенный набор | 8 | 4 | 36 |

В каждом семействе есть русский и английский диалог. Переводы одного сценария
всегда находятся в одной части; это не независимые наблюдения. Train покрывает
все 24 инструмента. Разделение сделано по последовательностям действий, а не
случайным строкам. У отложенного набора также другие названия треков и исполнители.
Общие инструменты и правила намеренно совпадают: проверяется их применение.

## Как получены примеры

[scenarios.json](v1/scenarios.json) содержит только train/dev: запросы, синтетическое
начальное состояние, шаги учителя и ожидаемое конечное состояние каждого хода.
`$ref` в сценарии — ссылка на поле **предыдущей квитанции** инструмента, а не ID,
придуманный моделью. Этот синтаксис не попадает в обучающие сообщения.

[replay.ts](replay.ts) запускает сценарии через настоящие `AgentConversation`,
`AgentExecutor`, `WaveAgentTools`, `PlayerEngine` и `MemoryStorage`, с тестовым
аудиоадаптером. Результаты команд берутся из исполнения. Проверяются параметры,
наличие ID в предыдущих результатах, порядок шагов, ошибки, конечные состояния
и сохранение указанной очереди/библиотеки/настроек. Вход каждого решения совпадает
с контекстом контроллера, преобразованным в экспериментальный формат `decision`.

После ошибки инструмента контроллер завершает ход. Объяснение ошибки в корпусе
идёт после **нового запроса пользователя**. Учитель не продолжает цепочку сразу
после отказа. Loading не выдаётся за playing; частично созданный плейлист не
объявляется наполненным; имеющийся трек не добавляется повторно без запроса.

Случайные публичные UUID заменяются стабильными псевдонимами отдельно для каждого
диалога с сохранением всех связей. Внутренние ID, пути и адреса файлов в сообщения
не попадают. Повторная генерация на том же коде воспроизводит содержимое файлов;
метаданные commit могут отличаться. Никаких команд в работающем плеере не выполняется.

## Проверка и экспорт

Нужны зависимости разработки Wave; веса, сервер моделей и сеть не нужны.
Из корня репозитория:

```sh
node --test scripts/agent-data.test.mjs
node scripts/agent-data.mjs validate
node scripts/agent-data.mjs export --out /absolute/path/to/new-dataset
node scripts/agent-data.mjs verify --bundle /absolute/path/to/new-dataset
```

Также доступны `pnpm agent:data` и `pnpm agent:data:test`. Каталог назначения
должен быть новым, его родитель — существовать. Перезапись запрещена. Экспорт
читает только фиксированный публичный источник; `--source` для него не разрешён.
Унаследованные переменные окружения с приватным источником игнорируются CLI.
Vitest используется как уже имеющийся TypeScript runner для изолированного ядра.
CI проверяет данные на Linux, Windows и macOS без доступа к отложенному набору.

Экспорт содержит:

- `train.jsonl`, `dev.jsonl`: объекты `{"prompt":[...],"completion":[...]}`;
- `index.jsonl`: ID диалогов и решений, часть, язык, семейство и рубрика;
- `traces.jsonl`: реальные квитанции и проверенные состояния для аудита;
- `manifest.json`: происхождение, число примеров, SHA-256 файлов, исходников и контракта.

**Обучать нужно только токены `completion`.** В `prompt` есть предыдущие ответы
ассистента и результаты инструментов: они должны быть полностью исключены из
функции потерь. Простое включение assistant-only loss для всего диалога этому
требованию не соответствует: старые ответы повторяются в нескольких префиксах.
`completion` содержит одно сообщение ассистента с `{"decision":...}` без Markdown.
Одинаковая форма применяется и для финального ответа, и для вызова инструмента.

Адаптер конкретного тренера и токенизатор ещё не добавлены. Перед обучением нужно
проверить шаблон чата, границу prompt/completion, маску токенов и длины на выбранном
токенизаторе. Нельзя молча обрезать сообщения или обучать на квитанциях инструментов.
Dev можно использовать для выбора checkpoint; отложенный набор — нельзя.

## Изоляция от оценки

Публичный `evals/wave-agent/v1` не изменён и не экспортируется в train/dev.
Валидатор отклоняет совпавшие ID/семейства между частями, одинаковые запросы и
сильное лексическое сходство с публичным v1. Для будущих изменений публичного
корпуса используются [хеши отложенного набора](v1/holdout-registry.json): семейства,
нормализованные запросы и трёхсловные фрагменты. Это защита от механического
смешивания, **не доказательство отсутствия смысловых перефразировок**.

Не включайте публичные проверочные задания, их переводы и близкие перефразировки
в обучение. Новые обучающие примеры должны исходить из самостоятельных сценариев,
а не из исправленных ответов на конкретные тестовые строки. Отложенный набор
написан и проверен тем же автором, что и train/dev; независимой проверки другим
человеком ещё не было. Код, валидный JSON и совпадение состояний не доказывают,
что любой текст учителя идеально соответствует намерению пользователя.

Закрытые исходники и эталоны находятся **вне Git**. В этом рабочем окружении:

```text
~/.local/share/wave-agent/datasets/seed-v1/
~/.local/share/wave-agent/holdouts/seed-v1/
```

В Unix каталог имеет права 0700, файлы — 0600. Это локальное разделение доступа,
а не шифрование и не внешний независимый хранитель. Хеши в Git не восстановят
потерянные файлы: приватный каталог нужно сохранять отдельно и не отправлять
в обучающий pipeline. Не печатайте эталоны в общедоступные логи.

Для создания **новой версии** отложенного набора из отдельного источника:

```sh
node scripts/agent-data.mjs seal --source /private/scenarios.json --out /private/new-holdout
```

Команда проверяет семейства и близкие запросы относительно train/dev, исполняет
все цепочки, сохраняет приватные `scenarios.json`, `inputs.jsonl`, `targets.jsonl`,
`traces.jsonl`, manifest и публичный `registry.json`. Источник и результат внутри
репозитория запрещены. В Git переносится только registry новой версии; после
использования тестов для настройки прежний набор больше нельзя считать отложенным.

Для оценки зафиксированного набора runner получает **только** `inputs.jsonl`
(`id`, `messages`). Ответы нужно сохранить как `{"id":"...","decision":{...}}`:

```sh
node scripts/agent-data.mjs score --bundle /private/frozen-holdout --responses /private/model-responses.jsonl
```

Оценщик проверяет целостность файлов и совпадение manifest с registry репозитория.
ID для проверки решений извлекаются только из квитанций в соответствующем входе.
Пропущенные, лишние и повторные ответы не дают успешного результата. Текст требует
ручного разбора по `manualReviewIds`, эталону и trace; совпадение категории не
доказывает правдивость. `productionReady` всегда false.

Это оценка следующего решения по **правильной истории учителя**. Она не измеряет,
справится ли модель с целым диалогом после своей ошибки. Для допуска по-прежнему
нужны отдельные цепочки с моделью, звук под нагрузкой и замеры на целевом ПК.

## Готовность к следующему шагу

128 обучающих решений из 14 семейств — стартовый материал для проверки обучающего
конвейера, а не достаточная выборка для надёжного агента. Нужны независимый разбор
текстов и разнообразия, расширение train/dev без доступа к отложенным ответам,
адаптер обучения с проверенной маской токенов, затем пробное дообучение и сравнение
исходных/дообученных/квантованных весов. Ни одна модель пока не выбрана для поставки;
данные, inference runtime и веса не добавляются в сборку приложения.

## Проверка этого этапа — 2026-10-24

Все 42 диалога / 190 целевых решений воспроизведены с проверками состояния.
Прошли 11 тестов CLI/изоляции и 4 проверки offline runner, TypeScript и ESLint.
Четыре сборки frontend подтвердили отсутствие данных в приложении; границы
настольного агента сохранены. Экспорт train/dev повторён целиком: хеши файлов
совпали побайтово. [Manifest публичного экспорта](v1/build-manifest.json) фиксирует
исходники и артефакты; полный экспорт хранится отдельно в указанном выше каталоге.

Самопроверка оценщика на собственных эталонах дала 36/36 совпадений и выделила
12 текстов для ручного разбора. Это проверка оценщика, **не результат модели**.
Ни локальная, ни облачная модель отложенные задания в этом этапе не получала.
Windows/macOS-проверки добавлены в CI; локально команды выполнялись на Linux.
