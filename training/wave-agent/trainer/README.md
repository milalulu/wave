# Пробное обучение LoRA для Wave

Добавлен отдельный **CPU-тренер**, который проверяет всю цепочку: фиксированный
train/dev → токенизация → loss только нового ответа → обновление LoRA → сохранение
в safetensors → повторная загрузка → сверка результата и неизменности базовой модели.
Python, зависимости и веса не входят в приложение, установщик или мобильную сборку.

Проверенный профиль — Qwen2.5 **0.5B Instruct**, только для технического прогона на
текущем ПК. Это другой размер модели, чем кандидат 1.5B из предыдущего сравнения.
Для 1.5B подготовлена и проверена токенизация; её обучение пока не выполнялось.
Точный commit каждой модели закреплён в [models.json](models.json), а не выбран
через изменяемую ветку `main`. Ревизия сохраняется и в `adapter_config.json`.

## Окружение

Испытано: Linux, Python 3.12, CPU-only PyTorch 2.9.0, Transformers 4.57.1,
PEFT 0.17.1 и Accelerate 1.11.0. Полные версии и хеши пакетов находятся в
[requirements.lock](requirements.lock). Это зафиксированная проверенная связка,
не рекомендация автоматически обновлять библиотеки до последних версий.
GPU/QLoRA, Windows и macOS для обучения этим тренером ещё не проверялись.

Из корня Wave, используя установленный `uv`:

```sh
uv venv --python 3.12 "$HOME/.local/share/wave-agent/trainer-venv"
uv pip sync --python "$HOME/.local/share/wave-agent/trainer-venv/bin/python" \
  --index https://download.pytorch.org/whl/cpu --index-strategy unsafe-best-match \
  --require-hashes training/wave-agent/trainer/requirements.lock
```

Пакеты устанавливаются в отдельное окружение. На текущем ПК оно занимает около
925 MiB, снимок весов 0.5B — около 954 MiB в кэше Hugging Face. Они остаются
доступны для следующих запусков. Глобальный Python и зависимости Wave не меняются.

Для следующих команд `TRAIN_PY` обозначает путь к Python этого окружения:

```sh
TRAIN_PY="$HOME/.local/share/wave-agent/trainer-venv/bin/python"
"$TRAIN_PY" -m unittest discover -s training/wave-agent/trainer -p 'test_*.py' -v
```

13 проверок маски, целостности и ограничений запуска работают без ML-зависимостей;
2 проверки autograd/PEFT требуют окружение и создают маленькую случайную Qwen2
без скачивания весов. В обычный CI добавлены только проверки без ML-зависимостей.

## Загрузка и подготовка

Сначала нужен публичный экспорт seed-v1, описанный в [основной документации](../README.md).
Тренер принимает только manifest этого корпуса и сверяет хеши train/dev/index/traces.
Отложенный набор не открывается. Команда `fetch` отдельно скачивает публичные
файлы с закреплённой ревизии; пользовательский токен не используется, удалённый
Python-код не исполняется, веса принимаются только в safetensors.

```sh
"$TRAIN_PY" training/wave-agent/trainer/train.py fetch --model qwen25-0.5b
"$TRAIN_PY" training/wave-agent/trainer/train.py fetch --model qwen25-1.5b --tokenizer-only

mkdir -p "$HOME/.local/share/wave-agent/prepared"
"$TRAIN_PY" training/wave-agent/trainer/train.py prepare \
  --model qwen25-0.5b \
  --dataset "$HOME/.local/share/wave-agent/datasets/seed-v1" \
  --out "$HOME/.local/share/wave-agent/prepared/new-seed-qwen25-05"
```

`prepare` использует только локальный кэш. Она проверяет **все** 128 train и 26 dev
примеров настоящим шаблоном чата. В обоих размерах Qwen2.5 получены одинаковые
длины: максимум 1993 токена в train и 1537 в dev. Потери вычисляются на 3926
целевых токенах train и 992 dev; 179573 токена контекста суммарно замаскированы.
Это число токенов во всём подготовленном корпусе, а не число токенов пробного обучения.

Подготовленный пакет содержит token IDs, attention mask, labels, метаданные ID/языка,
шаблон чата и manifest. Полный префикс с `add_generation_prompt=True` должен точно
совпасть с началом полного диалога. Проверяется обратное декодирование целевого
JSON и наличие завершающего токена. Литеральные управляющие токены чата в содержимом
отклоняются. Длинные примеры вызывают ошибку; скрытой обрезки и упаковки диалогов нет.

Все токены префикса, включая прежние ответы ассистента, имеют label `-100`.
Правый padding маскируется по позиции: настоящий EOS не исключается из обучения,
даже если ID padding совпал с EOS. Для batch size 1 выходные logits вычисляются
только для `completion_tokens + 1` позиций; **весь входной контекст сохраняется**.
Дополнительная позиция нужна для предсказания первого целевого токена. Отдельный
тест на Qwen2 сравнивает loss и градиенты с обычным полным расчётом.

## Ограниченный запуск

```sh
mkdir -p "$HOME/.local/share/wave-agent/training-runs"
"$TRAIN_PY" training/wave-agent/trainer/train.py train \
  --prepared "$HOME/.local/share/wave-agent/prepared/new-seed-qwen25-05" \
  --out "$HOME/.local/share/wave-agent/training-runs/new-pilot" \
  --steps 2 --dev-samples 2 --threads 2 --budget-seconds 600
```

По умолчанию выполняются **два** optimizer step, batch size 1, float32, AdamW
с learning rate 1e-4, gradient clipping 1, LoRA rank 4 / alpha 8 на q_proj/v_proj,
без dropout. Все базовые параметры заморожены. Входные примеры чередуются RU/EN
в фиксированном порядке. Для двух шагов это две команды паузы одного семейства,
а не обучение на всём корпусе. Отдельного перемешивания по эпохам, scheduler,
resume optimizer state или выбора лучшего checkpoint здесь пока нет.

Тренер проверяет свободные RAM/диск перед загрузкой. Начальные оценки: не менее
4 GiB доступной RAM для 0.5B и 10 GiB для 1.5B, плюс 3/5 GiB свободного диска.
Это консервативные ограничения запуска, не измеренные минимальные требования.
Перед очередным шагом обучение прекращается при доступной RAM ниже 1 GiB.
Проверка не резервирует память и не исключает давление на swap между шагами.

Родительский процесс ограничивает полное время дочернего процесса, включая
загрузку и верификацию адаптера. При таймауте/ошибке остаётся `failure.json` с
`incomplete`; такой каталог нельзя считать успешным checkpoint. Существующие
каталоги не перезаписываются. Артефакты разрешены только вне репозитория.
После `fetch` подготовка и обучение используют только локальные файлы; ни данные,
ни логи, ни веса не отправляются в облачные сервисы и не публикуются в Hub.

Успешный каталог содержит `adapter/`, `tokenizer/`, `progress.json`, `train.log`,
`request.json`, снимки исходников в `sources/` и `result.json`. Последний включает
ID реально использованных примеров, loss до/после, хеши файлов, ревизии, параметры,
время, sampled RSS процесса и подтверждение сохранения/загрузки. Peak sampled RSS
может пропустить короткие пики и не измеряет память всего устройства или плеера.
`productionReady` остаётся false. Для продолжения обучения нужен отдельный запуск;
этот адаптер автоматически в Wave не устанавливается.

## Что подтверждено и что осталось

[Отчёт первого запуска](runs/2026-10-24/README.md) содержит измерения технического
прогона, а не оценку качества команд. Dev loss — вероятность эталонных токенов
на правильной истории; её снижение не означает успешное управление плеером.
Отложенные задания и публичный v1 модели в этом этапе не предъявлялись.

Далее нужны независимый разбор и расширение корпуса, более длительное обучение
кандидата на подходящем оборудовании, оценка на dev с генерацией реальных решений,
затем отдельная оценка замороженной модели и многошаговых цепочек. Экспорт/квантование
для Ollama и измерение скорости, памяти и звука после дообучения ещё не выполнены.

Использованные первичные источники: [шаблоны чата Transformers 4.57.1](https://huggingface.co/docs/transformers/v4.57.1/chat_templating),
[PEFT LoRA](https://huggingface.co/docs/peft/v0.17.0/en/quicktour),
[карточка Qwen2.5 0.5B Instruct](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct).
Ревизии закреплены отдельно; доступность этих API проверена на установленных версиях.
