# Первичный отбор локальной модели — 2026-10-24

**Ни одна проверенная модель не допущена к повседневному управлению Wave.**
Qwen2.5:1.5b оставлена кандидатом для следующего эксперимента с форматом вывода
и компактным контекстом: она завершила набор, требует меньше памяти и лучше
прошла общую часть заданий. Это не выбор готовой модели для поставки и не результат
дообучения. Веса не встроены в приложение, настройки подключения не переключались.

## Условия

Linux x64, Intel Core i3-10100F, 8 логических CPU, 15 890 MiB RAM, Ollama 0.32.6.
GPU-ускорение недоступно; в запросах принудительно `num_gpu=0`, allocation каждого
ответа проверен на нулевую VRAM. Два потока, контекст 8192, Q4_K_M, JSON mode,
`think=false`, максимум 1024 выходных токена, temperature 0, seed 42, top_k 0,
top_p 1, repeat_penalty 1. Полный профиль, digest, размеры весов, хеши шаблона и
лицензии находятся в manifest каждого прогона.

Это ограниченный отбор двух небольших базовых вариантов и проба установленной
EditorAI. Установленные 7B-варианты не измерялись; их быстродействие не оценивалось.
Название Ollama `qwen3:1.7b` сохранено буквально; метаданные этого GGUF сообщают
`parameterSize: 2.0B`. Название тега не заменяет digest артефакта.

Профиль использует нативный `/api/chat`, а приложение — совместимый Chat Completions
транспорт с другими настройками по умолчанию. Это измерения заданного профиля,
не доказательство идентичного поведения UI. Greedy temperature 0 также отличается
от рекомендованного Qwen3 sampling. Результат не распространяется на все режимы модели.

Задания v1 и эталоны не менялись. Модель получала только системную инструкцию,
каталог инструментов, запрос и фиксированный синтетический контекст. Ни реальные
данные библиотеки, ни её токены/URL не использовались. Решения в однократных
прогонах не исполнялись. Не было подбора подсказки под полученные ответы.

## Качество следующего решения

| Прогон | Охват | Строго верных решений | Корректная схема | Итог |
| --- | --- | --- | --- | --- |
| [Qwen2.5:1.5b](qwen25-full/score.json) | Все 60 | 29/60 (48,3%) | 46/60 | Критические: 4/20; допуск не пройден |
| [Qwen3:1.7b](qwen3-partial/score.json) | 30 ответов, затем таймаут, 29 заданий не запущены | 9/30 полученных ответов | 11/30 | Частичный прогон; полного процента качества нет |
| [EditorAI v2](editorai-v2-timeout/manifest.json) | Первая проба screen | Ответ не получен за 60 с | Не измерено | Остановлен, модель выгружена |

На **одних и тех же первых 30 заданиях** Qwen2.5 дала 18 правильных решений,
Qwen3 — 9. В полном прогоне Qwen2.5: русский 16/32, английский 13/28.
Рабочий порог проекта — ≥95% решений и 100% критических случаев, плюс ручная
проверка текста и полного агента. Ни один результат не удовлетворяет этому порогу.
`score.json` частичного прогона технически имеет знаменатель 60 и 29 missing;
его поле accuracy нельзя выдавать за измеренный результат полного набора.

Показательные ошибки Qwen2.5: 1 минута 30 секунд превращается в 130 секунд;
неизвестная исходная громкость заменяется предположением; запрос удаления плейлиста
превращается в очистку очереди. Последняя команда корректна по схеме, но не по
намерению пользователя: один валидатор аргументов этого не обнаружит.
Qwen3 часто выбирает правильное название, но нарушает оболочку решения. Есть и
ошибки смысла: reset EQ выставляет девять полос в −12 dB, «следующим» меняется
на «в конец». На `queue-clear-ru` она превысила диагностический лимит 180 секунд.

Все несовпадения просмотрены отдельно: [Qwen2.5](qwen25-full/manual-review.json),
[Qwen3](qwen3-partial/manual-review.json). Совпавших текстовых решений для отдельной
rubric-проверки не оказалось. Читаемый текст с неверной схемой не исправлялся для
улучшения баллов. Публичный набор строгий: повторное чтение статуса вместо ответа
по фиксированному снимку считается несовпадением, хотя в живом чате оно может быть
разумным. Это ограничение набора сохранено в ручном разборе.

## Задержка и память

В смешанном наборе Qwen2.5 первый запрос занял 81,7 с, следующие 59 — p50 5,72 с,
p95 16,39 с. Qwen3: первый 91,6 с, следующие 29 завершённых — p50 10,14 с,
p95 21,80 с; отдельно один таймаут 180,1 с. Последний не входит в процентили
завершённых ответов. Задержки включают неверные ответы. Во время этих прогонов
шли обычные проверки кода; они не являются изолированным аппаратным бенчмарком.
В начале Qwen2.5 ещё завершалось скачивание второго кандидата.

Начальная [проба Qwen2.5 с лимитом 60 с](qwen25-timeout/manifest.json) также
завершилась таймаутом. Повышение до 180 с сделано только для диагностики, лимит
нативного HTTP Wave остаётся 60 с. Следовательно, работоспособность холодного
запроса в текущем приложении этим прогоном не подтверждена.

Ollama сообщил allocation 1304,3 MiB для Qwen2.5 и 2307,2 MiB для Qwen3.
Максимальная sampled anonymous memory cgroup сервиса в этих прогонах — примерно
1411 и 2390 MiB соответственно. Это разные показатели, **ни один не является RSS**.
`/proc` скрывает процессы Ollama в данном окружении, поэтому RSS/swap дерева
процессов записаны как null. Cgroup total включает файловый кэш, в том числе
скачанные веса, и не используется как размер модели. Peak по выборкам может
пропустить кратковременный пик. Работа с GPU-ускорением и минимальный целевой ПК
не проверены.

Отдельные [пять пар повторов Qwen2.5](qwen25-performance/metrics.json), без
параллельных сборок и скачивания моделей:

| Состояние перед запросом | Повторы | Верных решений | p50 | p95 / max |
| --- | --- | --- | --- | --- |
| Модель выгружена | 5 | 5/5 | 80,255 с | 81,696 с |
| Сразу после того же запроса | 5 | 5/5 | 2,589 с | 2,736 с |

Каждый раз использовалось одно задание `pause-ru`. Пять наблюдений недостаточны
для устойчивой оценки хвоста распределения: здесь p95 совпадает с максимумом.
«Выгружена» подтверждено `/api/ps`, но файловый кэш ОС не очищался. Быстрый повтор
может переиспользовать KV-кэш одинаковой подсказки; он не представляет произвольный
новый диалог. Для смеси запросов выше приведён отдельный результат.

Во время этих повторов peak sampled anonymous memory cgroup — 1388,5 MiB;
медианная средняя загрузка — 1,86 CPU после выгрузки и 1,68 CPU при повторе
(эквивалент занятых логических ядер). Полная память процесса остаётся неизвестной.
Это не подтверждение отсутствия помех воспроизведению.

## Цепочки действий

Qwen2.5 завершила **0 из 3 задач** в изолированном прогоне:

| Задание | Наблюдение | Время до остановки |
| --- | --- | --- |
| Найти → включить → громкость 30% | Смешаны аргументы нескольких инструментов, придуман ID; команда отклонена до исполнения | 83,6 с, с загрузкой модели |
| Добавить в конец, сохранив текущий трек | Неполный JSON без причины завершения stop; ответа для исполнения нет. Исходный трек продолжал играть в тестовом адаптере | 10,0 с |
| Создать и наполнить плейлист | Плейлист создан один раз. Затем выдуман ID трека без поиска; `unknown_reference`, остановка. В тестовом хранилище остался пустой плейлист | 19,5 с |

Сохранены [трассы и конечные состояния](qwen25-scenarios/scenarios.json),
[ручной разбор](qwen25-scenarios/manual-review.json) и снимок исходников сценариев.
Ни одного финального текстового ответа не было, поэтому отсутствие ложных
сообщений об успехе здесь не доказывает общую правдивость модели. Случайные ID
сессий записаны в трассе; повторный прогон может дать другую последовательность.
Исправление JSON-оболочки само по себе не научит модель сначала искать трек
и использовать только выданный приложением ID.

Сценарии используют реальные контроллер диалога, исполнитель и ядро Wave,
MemoryStorage и MockAudioAdapter. Пользовательский плеер и БД не подключались.
Это проверка изменения состояния, а не слышимого звука, UI или сетевых провайдеров.
Отмена, ошибки инструментов и дедупликация дополнительно покрываются обычными
регрессионными тестами с тестовой моделью; реальный LLM здесь не измерялся на
всех этих ситуациях.

## Следующий эксперимент

1. Зафиксировать отдельный профиль с принудительной схемой вывода и более коротким
   каталогом инструментов. Повторить одинаковые испытания исходных кандидатов;
   не исправлять ответы задним числом и не смешивать результаты профилей.
2. Уложить первый запрос в выбранный бюджет на минимальном ПК, затем измерить
   прерывания звука и полную память процесса при воспроизведении. Нынешние
   измерения не доказывают пригодность для устройств с малым объёмом RAM.
3. После этого готовить разрешённые обучающие диалоги и независимый закрытый
   holdout. Не включать v1, его переводы и близкие варианты в обучение. Сравнивать
   baseline, дообученную модель и квантованный результат на одном оборудовании.

Дообучение не выполнялось. Для Qwen runtime содержит Apache 2.0; официальные
карточки: [Qwen2.5-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct),
[Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B). У установленной EditorAI v2
runtime не вернул текст лицензии; права на распространение этого производного
артефакта данным прогоном не установлены.
Поля API и единицы: [Ollama Chat](https://docs.ollama.com/api/chat),
[Ollama running models](https://docs.ollama.com/api/ps).

Артефакты содержат снимки исходников runner и хеши неизменённых задач/контракта.
База Wave — `7e45a24`, worktree во время экспериментов был изменён. В ранних
60-секундных пробах снимки исходников ещё не сохранялись; они служат свидетельством
таймаута, а не самостоятельным воспроизводимым сравнением качества.

Проверки реализации стенда: 489 регрессионных тестов приложения, 9 тестов runner
с локальным поддельным HTTP-сервером и 3 теста evaluation CLI прошли. TypeScript
для приложения, Vite-конфига и сценариев, ESLint и настольная frontend-сборка
прошли. Три **модельных** сценария выше закономерно завершились с кодом 1;
это отрицательный результат оценки модели, а не успешная приёмка. Нативный Rust
в этом этапе не менялся; Windows/macOS и настоящий аудиовыход не проверялись.
